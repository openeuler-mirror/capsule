# 精简判定口径
只需要修复会影响 PPT 可用性的严重排版问题：
1. 图文上下分布时图片高度小于、等于或接近上方文字高度，导致图片明显偏小。
2. 图片加载失败、图裂、alt 文本兜底、空白图片框或明显的图片无法显示提示。
3. 图片或文字溢出容器、被截断、被容器边界裁掉、遮挡其他元素或覆盖关键内容。
4. 多个卡片或区块紧贴在一起、相互侵占位置、上下信息块之间没有可见间距或分隔。
5. 布局不合理导致大量空白：主体内容集中在一角、一列或很小区域，页面另一半或大块区域空置，信息密度异常低或视觉重心严重失衡。
6. 明显排版错乱、样式错误、元素重叠、整页空白或大面积空区、页脚/图例/组件错位、表格/列表/按钮结构破损。

# 强制修复流程
请在心中完成以下步骤，但最终不要输出分析过程，只输出完整 HTML：
1. 先判断根因属于哪一类：空间分配错误、容器约束错误、图片资源错误、栅格结构错误、内容密度过高、布局利用率过低、组件样式破损。
2. 如果问题来自空间分配、容器约束、栅格结构或内容密度，必须重排相关区域；不要只通过小幅修改 margin、padding、font-size、top、left 来碰运气。
3. 如果历史摘要显示相同区域或相同问题类型反复出现，说明局部修补失败，本轮必须采用更激进的布局重构策略。
4. 为主要区域设置明确稳定的尺寸约束，例如 flex/grid 比例、宽高上限、min-height/max-height、overflow 策略、图片 object-fit 和容器 gap。
5. 如果卡片内部文字被底部边界裁切、列表项只显示一部分、上下信息块互相侵占，优先重构该列的布局：增加该列可用高度或宽度、减少同列堆叠数量、改为两列/网格、移除 overflow hidden、使用 auto/min-content 高度、增加 gap，确保每个信息块内容完整显示。
6. 如果出现图片加载失败 / 图裂，直接移除出错的 img 元素及其占位容器，不要替换 URL、不要保留 alt 兜底、不要保留空白方框；随后重新排版让剩余内容自然填满空间。
7. 如果图文上下分布导致图片过小，优先压缩文字区并扩大图片区；如果仍无法解决，改为左右分布或重构为更稳的栅格布局。
8. 如果出现不合理大量空白，不要只放大字号、增加 padding 或拉伸单个卡片来填空；必须根据内容重构布局方案，例如改为左右分栏、多列网格、上下区域重新分配、增加信息分组、把单列列表拆为多列、让图文/数据/结论并列展示，使主要内容自然占用页面核心空间并保持视觉重心稳定。
9. 如果标题或关键词因字号过大产生异常断行，尤其是单个词组被拆成难以阅读的多行，应降低标题字号、调整标题容器宽度，或改成更均衡的左右/上下结构；不要让标题挤占主体内容空间。
10. 如果页面是封面、目录或章节页，也不能让要点列表只占据一小块区域并留下大面积空白；应重新分配标题区、要点区和装饰背景的比例，让标题、摘要、列表自然形成稳定视觉重心。
11. 不要删除与问题无关的文字、数据、标题、注释或业务信息；如果重排导致位置变化，必须保持信息完整。
12. 必须保留原 HTML 中的基础设施代码，包括 doctype、html/head/body 根结构、缩放脚本、外部 CDN 引用、字体设置和必要脚本样式。
13. 修改后在心中按“精简判定口径”逐项自检，确认没有 critical 问题后再输出。
